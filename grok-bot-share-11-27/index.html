全场核心 · 11–23 分钟

土豆姐的 Agent 思维。
这套东西我搬到 Muse、Hermes、Claude Code 上用过，都成立。

🥔 土豆姐 Lauren Tan（@poteto）：不是计算机科班出身，在 Netflix、Meta、Cursor 都工作过，现在是 SpaceX AI 里做 Grok Bot 的核心工程师。她把自己用 Agent 的经验全写了出来。

土豆姐的 Agent 思维 · 通用

一、一切关于信任

「不信任它的产出时，开 100 个 Bot，只会得到 100 份要返工的东西。」

1–5 个全程盯着
一走开就错
先带好 1 个盯着它把一件事
做到每次都对
信得过，再多开敢开 100 个的前提
是你信得过，不是胆子大

所以她说：先只用一个 Bot。拆分是为了专业化，不是为了显得团队大。我最后减到 3 个，产出反而稳了。

她对 Agent 的比喻：「刚入职、又失忆的员工」。它不记得你教过什么，所以它每犯一次错，你就多一次机会，把教训写成规则存下来。

土豆姐的 Agent 思维 · 通用

二、信任四步，别跳步

👀看着它做第一次肯定有错，当场纠正
→
📘写成手册做顺了，把方法写成一本操作手册存下来
→
✅一次做对只说一句，它就能做好
→
⏰设成定时任务到这一步，才有底气走开不管它

配套的一个动作，先复述，再动手：「先别动手。用你自己的话说说，我的目标是什么、你还有哪里不确定？」

趁还没动手先把误会说清，这时候改口最便宜。给任何 Agent 派大活，都适用。

土豆姐的 Agent 思维 · 通用

三、别打字了：语音「暴风式倾倒」

🎙️暴风倾倒用语音把想法、背景、约束、顾虑一次全倒出来，不组织、不审查
→
🪞让它复述整理Agent 把倾倒整理成结构，再用自己的话复述给你听
→
➕你只补漏纠正听复述就知道它哪里理解错了，补上缺的信息
→
▶️确认后再动手信息对齐了，才让它开始干活

打字时人会不自觉地自我审查、删减信息；语音倾倒倒出来的信息密度，是打字的几倍。

我的呼应：我现在布置复杂任务，基本都先语音倒一遍。返工明显少了。

土豆姐的 Agent 思维 · 通用

四、最大的错误：把流程当目标

流程填表 · 发邮件 · 发日报
只是中间动作
≠
目标只有两类
增收，或降本
  • 目标讲清，Bot 可能设计出精简 10 倍的路径
  • 「邮件发出去 ≠ 事情办完了」。「办完」指的是事情办成了，不是动作做完了
  • 派活只说三件事：什么不能做、做完拿什么给我看、什么情况停下来问我。具体怎么做，让它自己想
土豆姐的 Agent 思维 · 通用

五、验证，才是真正的瓶颈

她打了个比方，叫「早餐工厂」：一份早餐有吐司、咖啡和煮鸡蛋。吐司一分钟，咖啡一分钟，煮鸡蛋要三分钟。所以这家店一小时能卖多少份早餐，不看最快的，看最慢的那个鸡蛋。
Agent 干活也一样：它写东西快得很，慢的是你检查它写得对不对。检查跟不上，开再多 Agent，也只是多堆一堆没人验过的东西。

「『我修好了』不算数。给我看修之前失败、修之后通过的证据。」

改结构（最可靠）
自动检查
写成 Skill
靠人检查（她评价：没前途）
70% 土豆姐说，她们现在大约 70% 的用量花在验证上，不是花在干活上。干活越来越便宜，验活才是花钱的地方。

外加两条：给每个 Bot 写死一张「禁区清单」：绝对不能做什么。没事的时候，就闭嘴；重复的活，让它写成小程序自动跑，别每次亲手一步步做。写个小程序是一次的成本，亲手做是每次都烧钱。
顺序别反了：先把活做对，再谈自动化。里层的活要是垃圾，自动化只会把垃圾放大。

实战印证 · 我的一个月（每张卡下面，是我做错的地方）

这套思维，我各撞了一次

75%额度见底那一周11/20 周用量已用掉 75%，光一个外链定时任务就占了本周 6%
✗ 我做错的：一口气设了一堆定时任务，没人盯着也在跑，烧到 75% 才发现
3 处史料被读偏IKEA 那篇，AI 初稿有 3 处把史料读偏（原因、先后顺序、时间点），全程盯着才抓出来
✗ 我做错的：初稿写得通顺，我差点就直接发了。通顺和正确，是两回事
5 封没发出的外联信外链 Bot 只认我本人在它面前授权，别人转述不算；最后攒下 5 封草稿没发出去
✗ 我做错的：我想图省事，让别的 Agent 转达我的批准。Bot 没认，这规矩后来成了全队的铁律
结论

带走三句话

🏠先分清要管家还是团队再去选工具。模型是哪家的，反而没那么重要
👛预算看池子，不看标价$30 写在价签上，烧起来是另一回事：几摊活共用一个池子
🤝瓶颈是信任怎么建立先把一个带到能信、要证据、犯错就改规矩。这套换到任何 Agent 上都成立
